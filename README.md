# Yatfa Scout

Рабочая система соцсетей Романа: очередь на утверждение, лента отправленного, вопросы рынка, люди.
Код здесь; плейбук, факты о продукте и архив черновиков — в репозитории `sales-md` (`social/`).

## Как устроено

```
Postgres (база social)  ←—  soc (консоль, для агента)
        ↑
        └—— web (localhost:4177, для Романа)
```

- **База `social`** на локальном Postgres. Строка подключения — в `.env` (в гите её нет).
- **`soc`** — консоль агента. Читает очередь, добавляет черновики, записывает итоги. **Сама ничего
  не публикует в сети.** `soc sent <id>` отказывает, если черновик не в статусе `approved`.
- **Веб** — один экран для Романа: очередь с кнопками, лента, вопросы, ответы, люди.

## Жизненный цикл черновика

`waiting` → (Роман жмёт «Отправляй») → `approved` → (агент отправляет через браузер, `soc sent`) → `sent`.
Или `skipped`. Кнопка «Отправляй» меняет **одну** строку; остальные не трогает — это то же правило
«один текст — одно разрешение», только оно теперь зашито в данные.

## Запуск

```
npm install
node bin/soc.mjs migrate        # схема (идемпотентна)
npm run web                      # http://127.0.0.1:4177
node bin/soc.mjs help            # команды агента
node bin/soc.mjs export          # копия в JSONL -> sales-md/social/data (чтобы история жила и в гите)
```

Перенос исходных данных из `sales-md/social/data/*.jsonl` — `node bin/import.mjs` (разово).

## Воронка лидов

Одна строка на человека — `leads.person` уникален. Стадии по порядку: `candidate` → `commented` →
`connected` → `talking` → `client` / `dead` — кандидат, прокомментировали (ждём их хода), коннект
принят, сами написали, клиент / закрыт. В вебе это вкладка «Лиды».

```
node bin/lead.mjs list                                             # лиды по стадиям воронки
node bin/lead.mjs add --person <people-id> [--stage --url --pain --next]
# постановка в воронку; повторный вызов обновляет: без --stage стадия возвращается в candidate,
# pain и next заполняются, только если переданы (иначе остаются прежние)
node bin/lead.mjs stage <id> --stage <стадия>                      # перевести лид на стадию
```

Тексты воронки идут через общую очередь черновиков: `connect` (заявка с запиской) и `dm` (личка
после реакции) — такие же виды `drafts.kind`, как остальные, тот же цикл `waiting → approved`.
Ничего не отправляется автоматически.

## Правила

- Воронка лидов: **цель — входящее от них**. Комментарий в их посте → ждём реакции; тред затух — коннект с запиской; коннект принят — личка. Никаких массовых личок и рассылок.
- Ни пароли, ни строки подключения в репозиторий не попадают.
- Веб слушает только `127.0.0.1`.
- Схема меняется только через `schema.sql` (идемпотентный).
